QueueSystem – Production Candidate Release Manifest
====================================================
Date: 2026-09-24
Source: original uploaded QueueSystem.zip

Implemented / verified in source:
- Live SignalR updates for manager/employee staff dashboards.
- Customer registration broadcasts a live staff event.
- Customer tracking page receives per-ticket live updates and disconnects on terminal states.
- Near-turn notifications at remaining 2 and 1 numbers, with browser/system notification fallback, vibration/tone/banner when supported.
- Standard Web Push with VAPID for Push API browsers, including iPhone/iPad Home Screen web apps.
- Firebase FCM fallback path using Firebase Installation ID; data-only push payload to avoid duplicate foreground/background display.
- Bilingual customer form and tracking screen; language switch added to initial registration screen; tracking language follows the registration screen on successful redirect.
- After successful customer submission, tracking opens immediately and ticket/token are persisted in localStorage.
- Re-opening the site can restore the saved tracking page from localStorage.
- Terminal customer states: served/closed, transferred to manager, and skipped-expired after five subsequent queue calls; terminal UI includes administration message, tracking instructions, location text/image and WhatsApp link.
- Duplicate customer-number handling: calling a number activates ALL current-day active registrations carrying that same number; each customer's tracking channel receives the event. Employee lookup shows all duplicate registrations with company, unified number, time and state.
- Manager transfer view includes customer number, company, unified number, time, transferring employee, desk and note.
- Form open/close audit stores timestamp and employee who performed the action and broadcasts live system-state changes.
- Public read rate limit widened to avoid one shared office/public IP throttling 200+ waiting customers; write endpoints remain protected.
- Public tracking URLs use HTTPS-aware / reverse-proxy-aware origin construction.
- Original project files preserved; only additive production fixes/config/docs/icons were added and targeted source files changed.
