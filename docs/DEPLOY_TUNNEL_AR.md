# النشر + Cloudflare Tunnel (بدون فتح بورت وبدون أدمن)

## 1) بناء النسخة المحمولة (على جهاز التطوير)

### Windows
```powershell
cd QueueSystem
powershell -ExecutionPolicy Bypass -File publish.ps1
```

### Linux / macOS
```bash
cd QueueSystem
chmod +x publish.sh
./publish.sh
```

المجلد الناتج: `publish-win/` ويحتوي `QueueSystem.exe` + الملفات التابعة.

---

## 2) على جهاز المكتب (التشغيل اليومي)

1. انسخ مجلد `publish-win` إلى أي مكان (مثلاً `C:\QueueSystem`).
2. **لا تحتاج صلاحيات أدمن.**
3. قبل أول تشغيل:
   - افتح `appsettings.json`
   - غيّر `Security:JwtSecret` إلى نص عشوائي طويل (64 حرفاً فأكثر)
4. شغّل `QueueSystem.exe` بالنقر المزدوج.
5. افتح محلياً: `http://127.0.0.1:5000`

### حساب المدير الافتراضي (أول تشغيل فقط)
- Username: `admin`
- Password: `[لا توجد كلمة مرور افتراضية — استخدم QUEUE_ADMIN_PASSWORD]`
- غيّر كلمة المرور فوراً من واجهة المدير بعد إنشاء حساب جديد.

---

## 3) Cloudflare Tunnel (وصول العملاء من إنترنت الجوال بدون فتح بورت)

### لماذا النفق؟
- العملاء على إنترنت هواتفهم يحتاجون رابطاً عاماً.
- جهازك لا يفتح أي بورت وارد (Inbound).
- `cloudflared` ينشئ اتصالاً **خارجياً فقط (Outbound)** إلى Cloudflare.

### التثبيت (مرة واحدة)
1. حمّل النسخة الرسمية لـ Windows:
   - https://github.com/cloudflare/cloudflared/releases
   - اختر `cloudflared-windows-amd64.exe`
2. أعد تسميته إلى `cloudflared.exe`
3. ضعه **بجانب** `QueueSystem.exe`

### التشغيل
- عند تشغيل `QueueSystem.exe` سيحاول تشغيل النفق تلقائياً إذا وُجد `cloudflared.exe`.
- راقب نافذة البرنامج: سيظهر سطر مثل:
  ```text
  الرابط العام: https://xxxx-xx-xx.trycloudflare.com
  ```
- هذا الرابط هو ما تعطيه للعملاء والموظفين (خارج المبنى).

### تشغيل يدوي (بديل)
إذا عطّلت النفق التلقائي في الإعدادات:
```text
cloudflared.exe tunnel --url http://127.0.0.1:5000
```

### ملاحظات
- رابط `trycloudflare.com` المجاني يتغير عند كل إعادة تشغيل (مناسب للتجربة).
- لاستقرار الرابط بشكل دائم مجاناً: أنشئ حساب Cloudflare مجاني + Tunnel مسمّى مرتبط بدومين (اختياري لاحقاً).
- لا يفتح أي منفذ على الراوتر أو الجدار الناري المحلي.

---

## 4) مشاركة الروابط

بعد ظهور رابط النفق `https://YOUR-SUBDOMAIN.trycloudflare.com`:

| الاستخدام | الرابط |
|-----------|--------|
| تسجيل العميل | `https://.../form/` |
| متابعة الرقم | يصدر تلقائياً بعد التسجيل |
| الباحث | `https://.../employee/` |
| المدير | `https://.../manager/` |

---

## 5) قائمة تحقق سريعة قبل يوم العمل

- [ ] `JwtSecret` تم تغييره
- [ ] حساب المدير الافتراضي تُرك أو غُيّرت كلمته
- [ ] تم إنشاء حسابات الباحثين بأسماء عرض واضحة
- [ ] النظام «مفتوح» من واجهة المدير
- [ ] النفق يعمل ويظهر رابط HTTPS
- [ ] تجربة تسجيل رقم تجريبي + استدعاء من شباك

---

## 6) استكشاف أخطاء شائعة

| المشكلة | الحل |
|---------|------|
| لم يظهر رابط النفق | تأكد من وجود `cloudflared.exe` بجانب البرنامج وأن الإنترنت يعمل |
| العملاء لا يصلون | انسخ الرابط الجديد بعد كل إعادة تشغيل للنفق المجاني |
| فشل تسجيل الدخول | تحقق من القفل بعد محاولات فاشلة؛ انتظر أو أعد ضبط الحساب من قاعدة SQLite |
| الصفحة بطيئة على الهاتف | استخدم HTTPS من النفق وليس HTTP محلي عبر IP |
