# قائمة تسليم QueueSystem للإنتاج

هذه النسخة عُدلت على أساس الكود الموجود فعلياً في المشروع، مع الحفاظ على قاعدة البيانات الحالية وعدم حذف `queue.db`.

## 1. شرط HTTPS

- يجب تشغيل النظام على عنوان HTTPS حقيقي.
- إذا كان الموقع خلف Reverse Proxy، فالكود يبني رابط المتابعة من Origin/Forwarded headers قبل الرجوع إلى Host الداخلي.
- هذا يمنع إرسال رابط متابعة يبدأ بـ HTTP رغم أن العميل فتح الصفحة عبر HTTPS.
- Firebase Web Push يتطلب HTTPS في بيئة الإنتاج.

## 2. Web Push / VAPID + FCM الاحتياطي

المسار الأساسي للتنبيهات في النسخة الحالية هو Web Push القياسي، وهو ما يتيح دعم Safari Web Apps على iPhone/iPad، إضافة إلى متصفحات Push API الأخرى.

قبل التفعيل في الإنتاج: وضع المفتاح العام في `wwwroot/push-config.js`، وتفعيل `WebPush:Enabled` ثم وضع `WebPush:Subject` و`WebPush:PublicKey` و`WebPush:PrivateKey` على الخادم. المفتاح الخاص لا يوضع داخل GitHub.

يوجد FCM/FID كمسار احتياطي للمتصفحات المتوافقة مع Firebase Web Messaging، ويمكن تفعيله عبر `Firebase:Enabled` وبيانات `wwwroot/firebase-config.js` وService Account. Firebase Web SDK الحديث يوصي باستخدام FID بدلاً من registration token القديم.

## 3. iPhone / iPad

Web Push في iOS/iPadOS يعمل كتطبيق Web App مضاف إلى الشاشة الرئيسية. لذلك:

1. افتح رابط النظام في Safari.
2. اختر Share.
3. اختر Add to Home Screen.
4. افتح الموقع من الأيقونة الجديدة.
5. اضغط `تفعيل التنبيهات`.
6. وافق على الإشعارات من نافذة النظام.

بعد ذلك يحتفظ العميل برابط التذكرة محلياً، ويمكنه إعادة فتح الموقع ومتابعة الرقم.

## 4. Android

1. افتح رابط النظام عبر Chrome.
2. اضغط `تفعيل التنبيهات`.
3. وافق على إشعارات الموقع.
4. إذا تم رفضها سابقاً: Chrome > Settings > Site settings > Notifications > اسم الموقع > Allow.

## 5. الرقم المكرر

رقم العميل ليس مفتاحاً فريداً في قاعدة البيانات.

عند وجود أكثر من تسجيل بنفس الرقم:

- يحتفظ كل تسجيل بسجل مستقل.
- شاشة الباحث تعرض جميع التسجيلات لهذا الرقم مع بيانات الشركة والرقم الموحد ووقت التسجيل والحالة.
- عند استدعاء الرقم، تُستدعى جميع التذاكر النشطة التي تحمل نفس الرقم حتى يصل التنبيه لكل أصحاب الرقم، لأن النظام لا يفترض مسبقاً أي تسجيل هو الصحيح.
- التحويل للمدير يتم على مستوى `RegistrationId` للتسجيل المحدد، وليس بمجرد رقم العميل.

## 6. انتهاء الاتصال مع العميل

يتم إنهاء جلسة المتابعة اللحظية للتذكرة فقط عند وصول حالة نهائية:

- انتهاء الخدمة (`CLOSED` بعد استدعاء رقم تالٍ على الشباك).
- التحويل للمدير (`TRANSFERRED`).
- انتهاء مهلة عدم الحضور بعد خمسة استدعاءات لاحقة (`SKIPPED_EXPIRED`).

تبقى بيانات التذكرة في Local Storage حتى تظهر حالة النهاية نفسها عند إعادة فتح المتصفح.

## 7. إغلاق استقبال العملاء

إغلاق التسجيل لا يحذف التذاكر ولا يوقف متابعة الأرقام القائمة.

يسجل النظام:

- وقت آخر إغلاق.
- اسم المستخدم الذي أغلق الاستقبال.
- وقت آخر فتح.
- اسم المستخدم الذي أعاد الفتح.

وتظهر هذه البيانات في شاشة المدير.

## 8. التحديث اللحظي

القنوات الأساسية:

- SignalR للباحث والمدير.
- SignalR للعميل على تذكرة محددة.
- Polling احتياطي للعميل كل 15 ثانية إذا تعذر الاتصال اللحظي.
- Web Push قياسي للتنبيهات في الخلفية، مع FCM/FID كمسار احتياطي.

تسجيل عميل جديد يبث حدثاً فورياً إلى مجموعة الموظفين/المديرين.

## 9. التنبيه عند اقتراب الدور

ترسل المنظومة إشعار `NEAR` عند بقاء:

- رقمان أمام العميل.
- رقم واحد أمام العميل.

يوجد منع للتكرار لنفس مستوى الاقتراب حتى لا يتلقى العميل نفس تنبيه الاقتراب أكثر من مرة لنفس الحدث.

## 10. الذروة

تم رفع حد القراءة العامة لأن العملاء قد يتشاركون نفس عنوان IP عند استخدام شبكة المؤسسة، مع إبقاء حد منفصل على عمليات الكتابة.

يوجد كذلك Queue داخلي موحد لإرسال Web Push/FCM في الخلفية حتى لا ينتظر تنفيذ الاستدعاء استجابة خدمة الإشعارات.

هذا تصميم لتحمل العدد المستهدف، لكنه لا يغني عن اختبار تحميل حقيقي على خادم MonsterASP نفسه قبل الإطلاق النهائي.

## 11. اختبار قبول الإنتاج

نفذ الاختبارات التالية على عنوان HTTPS الحقيقي:

1. عميل عربي يسجل ثم ينتقل مباشرةً إلى المتابعة.
2. عميل يغير اللغة إلى English وتتحول كامل واجهة المتابعة ورسائل النهاية والتعليمات والواتساب.
3. Android: تفعيل Push ثم إغلاق الصفحة واستدعاء الرقم لاحقاً.
4. iPhone: Add to Home Screen ثم تفعيل Push ثم اختبار استدعاء الرقم من الخلفية.
5. تسجيل عميلين أو أكثر بنفس الرقم والتأكد من وصول الاستدعاء لكل واحد.
6. البحث بهذا الرقم من شاشة الباحث والتأكد من ظهور جميع التسجيلات.
7. تحويل تسجيل مكرر واحد فقط للمدير والتأكد من بقاء التسجيلات الأخرى بحالاتها الصحيحة.
8. تخطي رقم ثم استدعاء خمسة أرقام لاحقة والتأكد من وصول `SKIPPED_EXPIRED` بعد اكتمال الخمسة.
9. استدعاء رقم تالٍ على نفس الشباك والتأكد من إغلاق الرقم السابق بعد خدمته.
10. إغلاق استقبال العملاء ثم تسجيل الدخول كمدير والتأكد من ظهور وقت الإغلاق واسم المنفذ.
11. إغلاق المتصفح أثناء الانتظار ثم فتحه ثانية والتأكد من استعادة التذكرة من الرابط/Local Storage.
12. اختبار 200 عميل متابعة على الأقل في وقت متقارب على السيرفر الحقيقي.

## 12. بيانات لا يجوز اختراعها

قبل اعتماد النسخة النهائية مع العملاء يجب إدخال القيم الحقيقية الخاصة بجهة العمل:

- اسم الإدارة بالعربية والإنجليزية.
- وصف موقع الإدارة بالعربية والإنجليزية.
- صورة موقع الإدارة الحقيقية (`Administration:LocationImageUrl`).
- رقم واتساب الإدارة إن كان مختلفاً عن القيمة الافتراضية الحالية.
- Standard Web Push public VAPID key في `wwwroot/push-config.js`.
- VAPID private key على السيرفر بشكل آمن.
- Firebase Web App config وService Account فقط إذا فُعّل مسار FCM الاحتياطي.
