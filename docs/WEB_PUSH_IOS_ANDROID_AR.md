# Web Push على الهواتف — دليل تشغيل الإنتاج

## لماذا يوجد مساران؟

النظام يستخدم Web Push القياسي + VAPID كالمسار الأساسي. هذا يجعل اشتراك المتصفح نفسه قابلاً للإرسال إلى نقطة الدفع التي ينشئها المتصفح، بما في ذلك Safari Web Apps على iPhone/iPad. يوجد FCM/FID كمسار احتياطي للمتصفحات التي تستخدم Firebase Web Messaging.

## iPhone / iPad

شرط iOS/iPadOS: 16.4 أو أحدث لدعم Web Push في Web Apps المضافة إلى الشاشة الرئيسية.

1. افتح رابط الإنتاج HTTPS في Safari.
2. اختر Share ثم Add to Home Screen.
3. افتح النظام من أيقونة الشاشة الرئيسية.
4. افتح تذكرة المتابعة.
5. اضغط Enable alerts / تفعيل التنبيهات واسمح بالإشعارات.

إذا كان الموقع مفتوحًا في Safari العادي ولم يكن Web App مضافًا إلى Home Screen، سيطلب النظام ذلك قبل التفعيل.

## Android

1. افتح رابط HTTPS.
2. افتح تذكرة المتابعة.
3. اضغط Enable alerts / تفعيل التنبيهات.
4. وافق على إذن الإشعارات.
5. عند رفض الإذن سابقًا، افتح إعدادات الموقع في المتصفح وأعد السماح بالإشعارات.

## رابط المتابعة

يتم حفظ التذكرة ورمز المتابعة محليًا، لذلك إغلاق المتصفح لا يلغي التذكرة. عند فتح الموقع مرة أخرى من نفس الجهاز، يعاد تحميل آخر تذكرة محفوظة ثم يتم التحقق من الخادم.

## قبل التشغيل العام

- HTTPS حقيقي.
- publicVapidKey صحيح في `wwwroot/push-config.js`.
- VAPID private key محفوظ خارج GitHub.
- `WebPush:Enabled=true`.
- اختبار إشعار الصفحة مفتوحة.
- اختبار إشعار الصفحة في الخلفية.
- اختبار iPhone Web App.
- اختبار Android.
